# Intake Gate response

Use this response when the author has not supplied enough material for a trustworthy design document. This is a blocking response. Do not produce the final template, a partial filled document, invented Metrics, or a guessed Design Solution.

## Required first response

Start with a brief statement such as:

> مسئله را دریافت کردم. قبل از نوشتن سند، چند بخش مهم هنوز مشخص نیست. ابتدا موارد موجود و کمبودها را بررسی می‌کنم و بعد از پاسخ شما Draft را می‌نویسم.

## Audit what was received

Use a compact table:

| بخش | وضعیت | چیزی که دریافت شد |
|---|---|---|
| Context / Problem | Received / Partial / Missing | ... |
| Goals & Non-Goals | Received / Missing | ... |
| Evidence | Received / Missing | ... |
| Metrics | Received / Missing | ... |
| Research & Insights | Received / Missing | ... |
| Benchmarks | Received / Missing / Not applicable | ... |
| Design Exploration | Received / Missing | ... |
| UX Flow | Received / Missing / Not applicable | ... |
| Design Solution | Received / Missing / Not applicable | ... |
| Open Questions | Received / Missing | ... |
| Post-Launch | Received / Missing / Not applicable | ... |

Do not label a missing section `Not available` or `Not applicable` until the author confirms that status.

## Questions for Problem-only input

Ask all applicable questions in one grouped response. The author may answer with text, a link, or an explicit status such as `ندارم`، `Not available`، `Not applicable` or `Skip`.

### Context and Problem

1. وضعیت فعلی سیستم دقیقاً چیست؟
2. رفتار واقعی کاربر را چگونه مشاهده یا ثبت کردید؟
3. این Problem از نوع User pain، Business impact، Opportunity gap یا Competitive gap است؟
4. Impact مسئله چیست؟ خطا، ریسک، drop، کاهش adoption، revenue، retention یا مورد دیگر؟
5. چه Evidenceای Problem را پشتیبانی می‌کند؟ لینک یا فایل آن را بفرستید.

### Goals and scope

6. کاربر بعد از این کار چه چیزی را باید بهتر انجام دهد؟
7. Business outcome یا Success direction چیست؟
8. Scope این نسخه چیست؟
9. چه چیزهایی Non-Goal هستند یا به فاز بعد می‌روند؟

### Metrics

10. Primary Metricها چیستند؟
11. Secondary Metricها یا Guardrailها چیستند؟
12. برای هر Metric، Baseline، Target، Timeframe، Data Source و Owner چیست؟
13. اگر Metric ندارید، آیا باید `Not available` ثبت شود؟

### Research and benchmarks

14. چه Researchای انجام شد؟ روش، Segmentها و تعداد مشارکت‌کنندگان چه بود؟
15. سؤال‌های اصلی Research چه بودند؟
16. لینک Research، Analytics، گزارش یا خروجی تحلیل کجاست؟
17. چه رقبا یا Benchmarkهایی بررسی شدند؟ لینک Figma یا منبع آن‌ها را بفرستید.
18. آیا باید Figma را مستقیم بررسی کنم؟

### Design process

19. چه Design Optionها یا ایده‌هایی بررسی شدند؟
20. Pros و Cons هر Option چه بود؟
21. کدام Option رد یا انتخاب شد و چرا؟
22. Iterationها و تغییرات مهم چه بودند؟ لینک Figma هر مرحله را بفرستید.
23. UX Flow، Screenها، Componentها و Interactionها چه هستند؟

### Follow-up

24. تصمیم فعلی چیست: Proceed، Iterate، Defer یا No change؟
25. Open Questionهای باقی‌مانده چیست؟
26. بعد از Launch چه چیزی باید بررسی شود؟

## Stop condition

After asking these questions, stop and wait. Do not write the design document in the same response unless the author has already supplied the answers in the current message. On the next turn, update the audit, ask only remaining questions, and draft only after the gate passes.
